Why it's broken today

Verified in code: the registry is read-rich but write-poor and demand-poor.

One real write path = a GitHub PR
Even /submit ("no GitHub needed") just builds YAML in the browser and opens GitHub's new-file editor — still needs a GitHub account + fork/branch/commit/PR literacy. A marketer hits a wall; conversion ≈ 0.
No backend for programs
755 static YAML → programs.json at build. Supabase exists but only for votes/analytics — no programs/users/applications, no auth, no claim.
Demand side doesn't exist
A program page's only action is an outbound Apply → the brand's external signup. OpenAffiliate mints no link, captures no partner, sees no conversion.
CI has a hole
pr-programs.yml validates + verifies + auto-merges, but calls scripts/enrich-program.ts which doesn't exist (|| true no-op). Dedup/logo/enrich silently skipped.

The five flows (concrete)

Two front-ends, one source of truth. Developers keep PRs; everyone else gets a form / CTA that lands the same YAML behind the scenes.

B · No-code "List your program"P0
  1. Paste product URL → AI auto-drafts the listing
  2. Review/edit in a friendly form (no YAML shown)
  3. Email magic-link (no GitHub, no password)
  4. "Submit for review" → submissions table → status page
  5. Clean → bot opens PR → CI auto-merges → live in minutes
  6. Email: "claim & verify for the Verified badge"

Trust model & roadmap

Trust tiers (volume vs curation)

Community — self-served / auto-discovered, verified:false. Frictionless single submit.
Claimed — owner verified via DNS TXT (authoritative) or email-on-domain (fallback) → editable, verified:true.
Stripe-verified — Affitor-run, real money flows. "Verified by Stripe" — the payout-credibility anchor.
Rules: single submit frictionless; bulk gated by review; precedence owner > network > community. Listing free forever — money only on the Affitor engine.

Roadmap

P0enrich.ts · /api/submit + submissions table + /admin + bot-PR · no-code /list · demand CTA branch → unlocks B + D-creator
P1Claim/verify (DNS TXT + email) + magic-link identity · agent write tools · owner dashboard → ownership + Verified pipeline
P2Bulk network import · Affitor flywheel (claim → run on Affitor) · native partner accounts → unlocks C + monetization

The discovery layer is mature for all four personas; the transaction layer is missing. Both gaps converge on two primitives — a no-code server intake (form → bot PR) and email magic-link identity. Ship those two and B, C, and D unlock together, with Affitor as the monetized engine the technical and trust-sensitive personas graduate into. Discover (open) → claim (own) → run on Affitor (engine).
